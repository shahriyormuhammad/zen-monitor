# Stocks And Cost Source

## 1. Откуда берётся себестоимость в PnL

Источник себестоимости для расчёта прибыли:

- экран `Себестоимость` (`/costs`) — источник правды по ручным затратам на SKU;
- основные поля хранятся в `unit_economics_manual_inputs.manual_fields`;
- `Товар закупка` дополнительно синхронизируется в `unit_economics_configs.cost_price`
  как legacy fallback для расчётов и старых интеграций.

Как это применяется в расчётах:

- в `AnalyticsEngine` используется полная себестоимость единицы:
  `Товар закупка + Доставка до ФФ + Упаковка + Фулфилмент + Доставка до ВБ`;
- `Доставка до ВБ` считается как средняя по выбранным в `/costs` складам;
- если ручных данных нет, применяется fallback закупочной цены из
  `unit_economics_configs.cost_price`, иначе используется `0`.

Это означает:

- изменение себестоимости пересчитывает текущие показатели во всех разделах;
- дата `effective_from` у `unit_economics_configs` больше не задаёт исторический
  срез для полной себестоимости, используется последняя актуальная закупочная цена;
- в `/costs` можно скопировать cost-поля в выбранные SKU той же модели через
  колонку `Склейка`.

## 2. Вкладка `Остатки` (`/stocks-v2`)

Назначение:

- объединить три контура остатков: `WB`, `свой склад`, `в пути из Китая`;
- показать локализацию спроса;
- дать готовый план поставки по SKU.

### Источники данных

- `raw_api_stock_sizes` — фактическая матрица WB по регионам/складам;
- `raw_api_orders` — fallback спроса, если нет валидного локализационного среза;
- `own_stock_batches` — партийный учёт своего склада и склада Китай;
- `own_stock_movements` — журнал приходов, списаний и корректировок;
- `production_orders` / `production_order_lines` — производство и путь из Китая;
- `wb_supply_writeoffs` — идемпотентный учёт автосписаний по WB FBW-поставкам.

### Базовые расчёты

Для каждого SKU:

- `dailyDemand`:
  - сначала из `stock_sizes.orders_count / days`;
  - fallback из `raw_api_orders / days`.
- `targetTotalUnits = ceil(dailyDemand * targetDays)`
- `targetWbUnits = ceil(dailyDemand * wbTargetDays)`
- `shortageTotalUnits = max(0, targetTotalUnits - (wb + own + transit))`
- `shortageWbUnits = max(0, targetWbUnits - wb)`
- `shipNowFromOwn = min(ownStock, shortageWbUnits)`
- `reserveFromTransit = max(0, shortageWbUnits - shipNowFromOwn)`

Локализация и план размещения:

- берутся доли заказов/остатков по регионам;
- по дефицитным регионам строится приоритетный план, куда отправлять поставку в первую очередь.

## 3. Сборка поставки и автосписание

На страницах `Остатки v2` можно:

- вести партии `своего склада` и `склада Китай`;
- видеть движения по SKU и ручные корректировки;
- смотреть журнал автосписаний и расхождений в `/stocks-v2/wb-supplies`;
- выбирать горизонт планирования (`targetDays`, `wbTargetDays`);
- выгружать CSV `Скачать план поставки CSV` для сборки отгрузки.

Ночной job `wb-supply-writeoffs-nightly`:

- ищет WB FBW-поставки за окно `WB_SUPPLY_WRITEOFF_LOOKBACK_DAYS`;
- берёт только принятые WB поставки (`statusID` 5/6), плановые/виртуальные поставки не списывает;
- при первом обнаружении принятой строки списывает заявленное количество со своего склада FIFO;
- сравнивает заявленное `quantity` и принятое WB `acceptedQuantity`;
- при расхождениях, доприёмке WB или нехватке своего склада отправляет Telegram-уведомление без повторных дублей.

# 0001 - Проектная память по принципу Karpathy

## Статус

accepted

## Контекст

Проект долгоживущий: много финансовых формул, Wildberries-источников, ручных настроек, согласований и эксплуатационных правил. Если держать решения только в чатах, контекст теряется, а следующие изменения начинают повторять старые ошибки.

Нужна не пользовательская память продукта, а память разработки и эксплуатации проекта.

## Решение

Создать контур `docs/knowledge/`:

- `INDEX.md` - входная точка.
- `raw/` - сырые материалы.
- `wiki/` - вычищенные правила проекта.
- `decisions/` - короткие записи решений.
- `health/` - правила проверки актуальности.

Добавить `npm run knowledge:health`, чтобы быстро проверять минимальную структуру и обязательные источники.

## Последствия

- Важные решения теперь фиксируются рядом с кодом.
- Новые сессии Codex/LLM могут быстрее восстановить контекст.
- Документация не должна разрастаться бесконтрольно: в `wiki/` попадает только выжимка.
- При противоречии код и свежий decision record важнее старой wiki-страницы.

# Себестоимость и юнит-экономика

## Суть

Текущий принцип: `Себестоимость` - источник правды по затратам на единицу товара, а `Юнит-экономика` - калькулятор сценариев и заказа партии.

По-русски главная колонка полной себестоимости: `Себес полный с отгрузкой`
(бывшее `Итого за ед.`) / полная себестоимость единицы с доставками.

## Как работает сейчас

Полная себестоимость единицы считается так:

```text
Итого за ед. =
  Закупка
  + Доставка до ФФ
  + Упаковка
  + Фулфилмент
  + Доставка до ВБ
```

Технически это собрано через `buildFullLandedCostSql(...)`:

- `costPrice` - закупочная цена товара.
- `deliveryToFf` - доставка до фулфилмента.
- `packagingMaterial` - упаковка.
- `fulfillment` - фулфилмент.
- `selectedWarehouses` + `warehouseCosts` - выбранные склады и средняя `Доставка до ВБ`.

Данные лежат в:

- `unit_economics_manual_inputs.manual_fields` - основные ручные поля себестоимости и сценариев.
- `unit_economics_configs.cost_price` - старое хранилище закупочной цены, сейчас используется как fallback.

Важно: историческое имя таблиц `unit_economics_*` не означает, что дашборды должны тянуться из старой пользовательской вкладки юнит-экономики. Сейчас это общий слой ручных финансовых входов.

## Где используется

- PnL и dashboard берут полную себестоимость через `buildFullLandedCostSql(...)`.
- Склейки и финансовые агрегаты должны использовать полную себестоимость, а не только закупку.
- `Остатки 2.0` используют полную себестоимость для оценки рекомендуемой партии.
- `Юнит-экономика` показывает закупку отдельно, но сценарные расчеты должны учитывать полную себестоимость.
- В `/economics-v2` поля себестоимости read-only: `Товар закупка`, `Доставка до ФФ`,
  `Упаковка`, `Фулфилмент`, `Доставка до ВБ` и `Себес полный с отгрузкой`
  подтягиваются из раздела `Себестоимость`, чтобы не забивать одно и то же
  в двух местах.
- В `/costs` поля себестоимости можно копировать в выбранные SKU той же модели
  через колонку `Склейка`; сценарии юнит-экономики и план заказа при этом не
  затираются.
- `Procifry Agent API` в cost reports должен возвращать `purchasePrice` отдельно и `fullCostPerUnit` отдельно.

## Юнит-экономика для заказа

Текущий рабочий сценарий `/economics-v2`:

- поиск по SKU, артикулу продавца, бренду, штрихкоду и категории;
- фильтры: все SKU, с продажами, с себестоимостью, без себестоимости, к закупке, выбранные;
- массовый выбор найденных SKU и SKU с заполненным `purchaseQtyTotal`;
- массовое скрытие выбранных SKU через `products.is_hidden`;
- сводка выбранной партии: количество SKU, штук к закупке, полная стоимость, выручка выкупов, валовая прибыль, рентабельность, внутренний маркетинг;
- копирование ручных полей в цвета модели через выбор вариантов с поиском.
- Excel-импорт из юнит-экономики принимает сценарии, заказ партии, налог,
  маркетинг, ИЛ/ИРП; себестоимость в Excel из этого раздела не редактируется.

## Правила изменения

- Не путать `Доставка до ВБ` с логистикой WB до покупателя. Это наша доставка товара до Wildberries.
- `Товар закупка` - только цена товара у поставщика. Это не полная себестоимость.
- `Товар закупка` в юнит-экономике должен оставаться закупочной ценой, а не полной себестоимостью.
- Для валовой прибыли, PnL, остатков и склеек использовать полную себестоимость.
- При добавлении нового ручного поля документировать ключ JSONB в этой странице.
- Если меняется формула полной себестоимости, проверить dashboard, dynamics, stocks-v2, economics, Agent API.
- Если меняется UX заказа партии, не ломать массовый выбор, скрытие и сводку выбранной партии.

## Риски

- Старые названия `cost_price` и `unit_economics_configs` могут привести к ошибочному выводу, что используется только старая юнит-экономика.
- Если в расчетах взять только `purchasePrice`, прибыль будет завышена.
- Если в `Товар закупка` положить полную себестоимость, партия и маржа начнут задваивать доставки.
- `Доставка до ВБ` по складам считается средней по выбранным складам; при неправильном выборе складов цифры могут выглядеть завышенными.

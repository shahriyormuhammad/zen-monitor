### [P1] Idempotency ключи отсутствуют в advertising_bid_changes и advertising_auto_bid_runs

### [P1] sync-finances / sync-orders swallow errors — onFailure не триггерится

- **Category:** reliability
- **Files:** [`src/server/jobs/sync-finances.ts`](../../src/server/jobs/sync-finances.ts) (catch блок в step.run на строках ~94), [`src/server/jobs/sync-orders.ts`](../../src/server/jobs/sync-orders.ts) (~57)
- **Description:** Внутри `step.run(...)` ошибка ловится и возвращается объект `{ error: ... }`, а не пробрасывается наверх. Inngest не считает step «failed», поэтому штатный `onFailure: handleInngestFailure` (который, к счастью, вынесен в шаред helper) не срабатывает, алерт в TG не уходит. Тенант видит «completed» в UI при фактическом сбое.
- **Impact:** silent data loss per-tenant в финансах и заказах; staleSyncAlert не поможет, т.к. `finishedAt` всё равно записался.
- **Evidence:** в ретurn-object включается `error: ...`, значит функция сама «обрабатывает» — но вверх по цепочке это не сигнал фейла.
- **Recommended fix:** после логирования ошибки делать `throw err` (или `throw new NonRetriableError` для permanent-fail), ретрай-политикой Inngest займётся сама. Effort: **S**.

### [P1] Нет logrotate для app/inngest логов — inngest.log 858 MB

- **Category:** infra
- **Files:** `/etc/systemd/system/enterprise-wb-analytics.service` (на сервере, `StandardOutput=append:/var/log/enterprise-wb-analytics.log`), аналогично `enterprise-wb-analytics-inngest.service`, `/etc/logrotate.d/` (отсутствует файл для этого сервиса)
- **Description:** Systemd unit пишет stdout через `append:` в `/var/log/enterprise-wb-analytics*.log`, но в `/etc/logrotate.d/` нет конфига для них. По факту на сервере:
  - `enterprise-wb-analytics-inngest.log` = **858 MB**
  - `enterprise-wb-analytics.log` = 15 MB
  - `enterprise-wb-analytics-supabase.log` = 68 KB
  - `journalctl --disk-usage` = 3.9 GB (system default, не учитывает app-файлы)
  Логов inngest заметно больше т.к. self-hosted `inngest-cli dev` в режиме `INNGEST_DEV=1` логирует каждый webhook, шаг, таймер.
- **Impact:** при текущем темпе диск (сейчас 83%) забьётся за 2-3 дня. Это ломает Postgres WAL (fsync → readonly), нарушает сервис для всех тенантов, затрудняет восстановление.
- **Evidence:** `ssh goalbot 'ls -lh /var/log/enterprise-wb-analytics*.log'` (у меня нет прямого вывода, но infra-под-агент подтвердил 858 MB).
- **Recommended fix:** создать `/etc/logrotate.d/enterprise-wb-analytics`:
  ```
  /var/log/enterprise-wb-analytics*.log {
    daily
    rotate 7
    compress
    delaycompress
    missingok
    notifempty
    copytruncate
  }
  ```
  (copytruncate нужен потому что systemd держит открытый fd на append-файл). Опционально — переехать на `StandardOutput=journal` + `journalctl SystemMaxUse=500M`. Effort: **S**.

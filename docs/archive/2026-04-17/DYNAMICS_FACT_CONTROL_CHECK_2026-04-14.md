# Финальная контрольная сверка фактических чисел динамики (2026-04-14)

## Период и охват

- Период сверки: `2026-03-15..2026-03-23`
- Контур: `FACT_WB`
- Охват: все склейки обеих кабинетов (`7` групп)
- Проверка выполнена для блоков:
  - `Общая прибыль склейки` (групповой ряд)
  - `Поартикульно` (ряды SKU)

## Методика (без допущений)

Запущен отдельный скрипт независимой сверки:

```bash
set -a; source .env; set +a;
npx tsx scripts/verify_dynamics_facts.ts \
  --from 2026-03-15 \
  --to 2026-03-23 \
  --output-json output/dynamics-fact-check/final-2026-03-15_2026-03-23.json \
  --output-md output/dynamics-fact-check/final-2026-03-15_2026-03-23.md
```

Скрипт считает метрики напрямую из raw-таблиц (`realization`, `orders`, `sales`, `funnel`, `ad_costs/ad_clusters`, `paid_storage`, `unit_economics_configs`, `tenants`) и сравнивает с ответом `AnalyticsEngine.getGroupDynamics(...)` поле-в-поле:

- каждый день периода,
- каждая склейка,
- каждый артикул,
- каждая метрика динамики.

## Что было (до исправления)

Первый прогон (до фикса движка):

- `compared=13 608`
- `mismatches=131`

Структура расхождений:

- все расхождения были только в групповых процентах воронки:
  - `funnelAddToCartPercent`
  - `funnelCartToOrderPercent`
  - `funnelOrderToBuyoutPercent`
  - `buyoutPercent`
- поартикульная часть (`SKU`) расхождений не дала.

Причина:

- в группе проценты воронки перезаписывались последним SKU в итерации, а не вычислялись от агрегированных групповых количеств.

## Что стало (после исправления)

После фикса `getGroupDynamics` (групповые проценты считаются от суммарных количеств группы) повторный полный прогон дал:

- `compared=13 608`
- `mismatches=0`

Итог:

- на проверенном периоде `2026-03-15..2026-03-23` значения динамики совпадают с независимым пересчётом по фактам БД без расхождений.
